# Агент мониторинга активности

Консольный прототип фонового агента на C++17 для Windows. Раз в 5 секунд он запоминает процесс и заголовок окна на переднем плане и факт физического ввода за последние 5 секунд. Накопленные записи уходят на HTTP-сервер пакетом JSON.

## Сборка

Нужны CMake 3.16+ и компилятор C++17: Visual Studio 2019/2022 или MinGW-w64. Команды запускать из корня проекта, для Visual Studio — из Developer PowerShell.

```powershell
cmake -S . -B build
cmake --build build --config Release
```

Готовый файл: `build\Release\monitor_agent.exe` (у одноконфигурационного генератора — `build\monitor_agent.exe`).

Проверка сериализации очереди без сбора метрик:

```powershell
.\build\Release\monitor_agent.exe --self-test
```

## Запуск

В одном терминале поднимите приёмник, он печатает каждый пакет и отвечает `200`:

```powershell
python tools\demo_server.py --port 8080
```

В другом:

```powershell
.\build\Release\monitor_agent.exe --url http://127.0.0.1:8080/
```

Остановка агента — `Ctrl+C`. Перед выходом он пытается отправить остаток очереди, а если сервер недоступен — записывает его на диск.

`python -m http.server` для проверки не подходит: на `POST` он отвечает `501` и не показывает тело. Любой HTTP-ответ агент считает доставкой, поэтому такой сервер снимет пакет с очереди, но JSON вы не увидите. Используйте `tools\demo_server.py`.

## Параметры

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `--url` | `http://localhost:8080/` | Куда отправлять `POST` |
| `--storage` | `pending_metrics.json` | Файл неотправленной очереди |
| `--agent-id` | имя компьютера | Поле `agent_id` |
| `--sample-sec` | `5` | Интервал сбора, для отладки |
| `--flush-sec` | `30` | Интервал отправки, для отладки |
| `--batch-size` | `10` | Размер одного пакета |

Агент подключается напрямую, без системного прокси, чтобы локальный сервер не уходил во внешний proxy.

## Формат пакета

`timestamp` — время формирования пакета, Unix-секунды. `time` внутри записи — локальное время образца.

```json
{
  "agent_id": "DESKTOP-MIDDLE-C",
  "timestamp": 1792147320,
  "payload": [
    {
      "time": "2026-09-15 13:55:00",
      "process_name": "chrome.exe",
      "window_title": "ИНСАЙДЕР — Система мониторинга сотрудников",
      "user_active": true
    }
  ]
}
```

`user_active` равен `true`, если с момента последнего движения мыши или нажатия клавиши прошло не больше 5 секунд (`GetLastInputInfo`). Имя процесса — файл образа окна на переднем плане. Если процесс нельзя открыть, имя берётся из снимка списка процессов. Заголовок и имя уходят в UTF-8, спецсимволы в JSON экранируются.

## Очередь

Запись добавляется в память и сразу пишется в `--storage`. Отправка происходит, когда записей накопилось 10 или прошло 30 секунд. В один HTTP-запрос попадает не больше 10 записей; если их больше, агент шлёт несколько запросов подряд.

Если соединения нет, записи остаются в файле (не больше 100 штук, более старые вытесняются) и повторяются через интервал отправки. При следующем запуске сохранённая очередь отправляется сразу. Ошибка разбора файла не затирает его: файл переименовывается в `*.bad`, агент стартует с пустой очередью.

Доставка — не меньше одного раза. Если процесс оборвётся после ответа сервера, но до обновления файла, при следующем запуске тот же пакет может уйти ещё раз.

## Структура

- `src/collector.cpp` — активное окно и факт ввода (WinAPI)
- `src/http_client.cpp` — `POST` через WinHTTP
- `src/json_util.cpp` — пакет и файл очереди
- `src/storage.cpp` — атомарная запись очереди
- `src/main.cpp` — цикл сбора, отправки и остановки
- `tools/demo_server.py` — локальный приёмник

## Ограничения

Реализация для интерактивного сеанса Windows. Это консольный процесс, а не служба: окно агента само может оказаться активным, если оно на переднем плане. Отправка синхронная, недоступный сервер задерживает следующий образец на время таймаута соединения (несколько секунд).
